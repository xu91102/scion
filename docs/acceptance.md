# 验收标准与证据

状态只能为 PASS、FAIL、BLOCKED、NOT_RUN。PASS 需要满足该版本全部必要断言，FAIL 表示预期未满足，BLOCKED 表示缺失具体前置条件，NOT_RUN 表示未执行。报告必须同时记录代码版本、策略/用例版本、执行时间、入口和制品。

## M0 本地可重复检查

入口：`scripts/check.sh`。构建产物 `target/debug/scion` 支持 `evaluate <snapshot.json>`。

| ID | 场景 | 必要断言 | 证据 |
| --- | --- | --- | --- |
| F01 | 没有必要证据 | 审查、CI、验收缺任一项均 BLOCKED | orchestrator 测试 |
| F02 | 证据版本过期 | 仓库、PR、head/base/merge/policy 任一不匹配均 BLOCKED | orchestrator 测试 |
| F03 | 失败、阻塞、未执行 | 每类结果只有 PASS 满足条件 | orchestrator 测试 |
| F04 | 自审、空制品或重复结果 | 返回明确阻塞原因，不挑一个有利结果通过 | orchestrator 测试 |
| F05 | 自动合并默认关闭、必要人工确认 | 缺失策略或确认不能得到 ready | orchestrator 测试 |
| F06 | 无效输入 | 非完整 SHA、非法仓库、PR=0、未知 schema/字段和损坏 JSON 被拒绝或阻塞 | 库及实际 CLI 测试 |
| F07 | 完整示例与 CLI | 满足条件退出 0，阻塞退出 3，输入错误退出 2；全部输出标记 dry_run，未认证证据、未执行合并 | CLI 进程测试与 smoke |

这组检查验证的是基础代码与本地判断逻辑。`examples/*.json` 全部为虚构资料，不能证明 Agent 编码、GitHub 检查、真实验收或自动合并已接通。

## v0.1 真实外部流程（当前均 NOT_RUN）

| ID | 场景 | 通过标准与主证据 |
| --- | --- | --- |
| E01 | 任务到 PR | 真实编码运行、隔离 worktree、修改提交和实际 PR；记录任务与尝试关系 |
| E02 | 独立审查 | 最终提交上的审查，有独立执行身份、范围与发现；编码者自报不能满足 |
| E03 | 既有 CI | required checks 的真实 run ID、来源、提交及结论；伪造同名 check 不满足 |
| E04 | 真实功能验收 | 实际服务/页面/应用的顺序日志或真实图像/视频；关键断言与候选构建对应；人工复核关键制品 |
| E05 | 合并候选一致性 | 两个分别通过但组合失败的 PR 被阻止；head/base 变化后旧证据失效 |
| E06 | 自动合并与权限 | 测试仓库中只有可信策略满足才合并；未授权、缺人工确认、未知分支保护均阻塞 |
| E07 | 恢复与幂等 | 重复事件、网络中断、合并已成功但响应丢失、控制器重启均不重复创建/合并 |
| E08 | 主线回归 | 核对实际合并提交并运行主线检查；失败时停止后续自动合并并给出可操作原因 |

任何一个核心 E 用例未通过，不能宣称 v0.1 端到端交付完成。真实外部写操作只在用户指定或明确授权的测试仓库执行。

## 版本绑定

每份真实证据需绑定 repository、PR、head、base、候选 merge 提交及可信 policy 版本，并记录用例版本、执行环境和制品摘要。若构建还受仓库外依赖影响，报告同时保留依赖锁文件/构建制品标识。代码更新后重新评估相关检查，不把旧 PASS 覆盖到新提交。
