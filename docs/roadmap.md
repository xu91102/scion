# 开源首版大纲与实现顺序

首个可用版本 v0.1 的目标：在一个明确授权的测试仓库中，任务触发隔离编码，生成 PR，完成独立审查和现有 CI，留下真实功能验收证据，按可信规则合并，并记录主线回归结果。

当前已包含 **M0 基础架构、M1 只读观察与持久化、M2 工作区协调**。M2 支持本机 Docker Agent、尝试与时间预算、取消及草稿 PR 发布。参见 [Agent 使用说明](m2-agent.md)。验证层级见 [M1 使用说明](m1-observer.md)；不把示例、模拟 API 或单元测试视为 v0.1 完整交付。

| 顺序 | 模块与具体交付 | 可复核完成标准 |
| --- | --- | --- |
| M0 | Rust workspace、共享契约、纯判断内核、CLI、文档与本仓库 CI | 从干净 clone 构建；缺失、失败、重复和过期证据均阻塞；示例始终 dry-run；本地及 GitHub CI 通过 |
| M1 | GitHub 只读适配器、SQLite 任务/事件存储、权威检查汇总 | 对真实测试 PR 读取 head/base、checks、审查与来源；主线/PR 更新使旧快照失效；重复事件不重复推进；控制器重启后恢复 |
| M2 | Agent 编码执行、Git worktree、预算/取消、PR 创建与更新 | 在隔离测试仓库按验收任务产出真实提交和 PR；记录退出码和修改范围；两任务工作区不相互覆盖；取消后进程停止；重试不重复创建 PR |
| M3 | 独立 PR 审查、CI 失败反馈与有限修复 | 审查绑定最终 diff，有独立身份和发现；构造的缺陷被发现；失败 CI 的真实日志触发修复，新提交重新检查；超过修复预算停止 |
| M4 | 真实验收执行器、用例版本、日志/图片/视频及摘要 | 在实际运行的服务/网页/应用中执行事先配置的用例；故意破坏业务行为时判 FAIL，即使构建成功；缺关键节点为 BLOCKED；制品可打开并绑定候选构建 |
| M5 | 合并控制器、必要人工确认、GitHub 队列或严格保护下的串行合并、主线回归 | 仅对权威检查和真实验收均通过的同一版本合并；过期证据、基线竞态、自审、缺人工确认均阻止；断线重试不重复副作用；合并后保存真实提交与回归结果 |

实现按 M0→M1→M2→M3→M4→M5 推进，每一步的真实外部验证单独取证。首版可通过 CLI 或 GitHub issue/PR 事件触发，不增加管理后台和自研 CI 平台。

## v0.1 明确边界

- 一个配置仓库、一个控制器；多 Agent 编码，单仓合并协调。
- 优先适配一种可由命令行运行的编码工具，供应商通过执行适配器替换；不把模型能力当成验收结果。
- 复用现有 CI。功能验收由项目提供明确用例和可运行入口，自动发现测试依赖不是首版承诺。
- 自动合并默认关闭。启用时由维护者提供可信策略；无法建立可靠分支保护的仓库保持只读建议模式。
- 合并、发布和生产验收分别记录。v0.1 不自动发布生产。

## 端到端示范任务

在专门测试仓库中，为一个演示网页增加“导出 CSV”功能。验收要求明确文件内容、空数据行为和实际下载动作。系统应产出 PR、独立审查、CI run 和浏览器验收制品，并在策略允许时合并。

同一套演示必须覆盖：正常成功、CI 失败后修复、构建通过但业务验收失败、并发 PR 组合失败、检查期间主线变化、重复事件、控制器重启和需要人工确认的策略变更。不能只演示成功路径。

## 进入公开测试的条件

M1—M5 的上述外部用例在授权测试仓库有当轮证据；安装/升级/停止和恢复步骤可复现；已说明最小权限、数据保留和适用平台。未通过项保留 FAIL/BLOCKED，不以删除检查或降低验收标准完成发布。
